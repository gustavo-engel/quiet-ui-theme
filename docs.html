Testar as cinco opções

Formato, resultado e dependência

  • pdf: arquivo PDF direto, A4 horizontal, título e horário; usa jsPDF + AutoTable.
  • excel: planilha .xlsx; usa SheetJS. CSV não é XLSX.
  • csv: texto tabular .csv, UTF-8 com BOM, separador vírgula e CRLF; nenhuma biblioteca.
  • json: arquivo .json com título, horário, colunas e linhas; nenhuma biblioteca.
  • print: diálogo do navegador, com Salvar como PDF quando disponível. É diferente de gerar o PDF diretamente.

CSV/JSON funcionam sem rede. PDF/Excel carregam bibliotecas sob demanda pelo manifesto vendor.js; para uso offline, hospede-as localmente e ajuste o manifesto. Não adicione scripts CDN diretamente na página.

Contrato da tabela

  • Todos os formatos usam os mesmos resultados filtrados e ordenados, incluindo outras páginas carregadas. Cada raiz data-ui-data-table mantém suas ações independentes.
  • Configure data-export-title e data-export-file (nome simples, sem extensão). Troque todos os IDs, labels e referências ao copiar; mantenha a faixa de ações antes da busca.
  • O componente captura as linhas presentes na inicialização. Paginação no servidor ou carregamento posterior exige adaptar a fonte de exportação para buscar todos os resultados autorizados com os mesmos filtros e ordenação.
  • A extração usa texto das células: remove ícones decorativos e barras de progresso, junta espaços/quebras de linha e conserva percentuais escritos. Use cabeçalhos simples, sem colspan/rowspan, e igual número de células por linha. Colunas de ações também viram texto; se necessário, adapte a matriz compartilhada para excluí-las em todos os formatos.
  • O CSV coloca cada célula entre aspas e duplica aspas internas. Textos iniciados por sinais de fórmula recebem apóstrofo de proteção. JSON e XLSX mantêm valores como textos; não inferem números ou datas.
  • Formatos desconhecidos geram erro. Sem resultados, nenhum arquivo é preparado. Preserve status acessível, loading e recuperação do botão após sucesso ou falha. Arquivo preparado não confirma que o usuário o salvou.
  • A impressão mostra só a tabela selecionada e todos os resultados filtrados; depois restaura título e layout, inclusive ao cancelar. O rodapé global é ocultado na impressão.

Contrato JSON

exportedAt é o horário de geração em UTC ISO 8601. columns e rows mantêm a ordem da tabela. Arrays permitem cabeçalhos repetidos sem perder valores.

{
  "title": "Clientes",
  "exportedAt": "2026-09-08T15:30:00.000Z",
  "columns": ["Cliente", "Situação"],
  "rows": [["Aurora", "Ativo"], ["Brisa", "Pendente"]]
}

Personalize o rodapé

No rodapé gerado, versão, data e autoria vêm de themeRelease em theme.js; nome e descrição ficam no bloco do rodapé em renderShell(). A data representa a versão publicada, não muda a cada visita. Preserve as classes para manter espaçamento e comportamento mobile.

Para personalizar uma página, forneça o HTML abaixo dentro de .ui-workspace antes da inicialização. O shell respeita data-ui-footer e não gera outro rodapé. Troque os textos pela identidade do projeto; créditos devem corresponder às dependências realmente usadas.

<footer class="ui-footer" data-ui-footer>
  <div class="ui-footer-inner">
    <p class="ui-footer-brand">
      <strong>Meu projeto</strong><span>Uma descrição curta do produto.</span>
    </p>
    <p class="ui-footer-meta">
      <span>Versão 1.0.0</span>
      <time datetime="2026-09-08">08/09/2026</time>
      <span>Gustavo Engel</span>
    </p>
  </div>
</footer>

Modelos de autenticação

Abrir o catálogo e escolher entre login centralizado, dividido e corporativo. Copie a página completa: campos, rótulos, erros, botões, região de status e rodapé. Os três modelos usam usuário/senha e Microsoft, CyberArk e Google.

As páginas usam .ui-workspace para receber o rodapé global; não incluem os ganchos de sidebar ou topbar. Preserve autocomplete="username" e autocomplete="current-password", os IDs únicos e data-ui-password-toggle. Os logos ficam em assets/logos/; veja origens e diretrizes.

data-ui-auth-demo ativa a demonstração. O formulário data-ui-auth-form bloqueia o envio antes de habilitar seu fieldset; sem JavaScript, permanece desabilitado. Dados não são transmitidos, registrados ou persistidos pelo tema. O campo de senha é limpo após o resultado. O navegador pode aplicar seu próprio preenchimento automático.

Em “Testar estados”, selecione conclusão ou erro demonstrativo. data-ui-auth-status anuncia o resultado. Os botões data-ui-auth-provider="microsoft", "cyberark" e "google" são do tipo button, ficam fora do formulário e funcionam mesmo com campos vazios. Não criam sessão nem redirecionam nesta prévia.

Conectar ao seu backend

Retire data-ui-auth-demo e os controles de simulação. Substitua o comportamento demonstrativo pelo fluxo real do projeto e habilite o fieldset. Para login local, mantenha method POST, configure action, proteção CSRF e tratamento de erro no servidor. Não basta alterar action enquanto o handler de demonstração continua ativo.

<!-- Exemplo de rota da SUA aplicação; não existe no tema. -->
<form method="post" action="/auth/login">
  <!-- Token CSRF fornecido pelo servidor, campos username/password e submit. -->
</form>

// Execute somente na versão integrada, sem data-ui-auth-demo.
// Troque estas rotas pelas rotas de início de SSO do seu backend.
const routes = new Map([
  ["microsoft", "/auth/microsoft/start"],
  ["cyberark", "/auth/cyberark/start"],
  ["google", "/auth/google/start"],
]);
document.querySelectorAll("[data-ui-auth-provider]").forEach((button) => {
  button.addEventListener("click", () => {
    const route = routes.get(button.dataset.uiAuthProvider);
    if (route) window.location.assign(route);
  });
});

O backend inicia o protocolo escolhido, valida a resposta do provedor e cria a sessão. Senhas locais nunca são enviadas ao provedor SSO. Segredos de cliente e validação de credenciais pertencem ao servidor. As rotas acima são ilustrativas, não endpoints dos provedores. Microsoft Entra ID é identificado no botão pela marca Microsoft; as marcas mantêm cores e proporções próprias.

Ações em tabelas

Use ui-button is-secondary ui-table-action para ações por registro em tabelas básicas ou Data Tables. Ícone e texto permanecem visíveis, com área mínima de 44px e foco nativo. Use square-pen para Editar e eye para Visualizar. Para múltiplas ações, agrupe com ui-table-actions.

<td>
  <div class="ui-table-actions">
    <a class="ui-button is-secondary ui-table-action" href="forms.html"
      aria-label="Editar Área do cliente">
      <i data-lucide="square-pen" aria-hidden="true"></i> Editar
    </a>
    <button class="ui-button is-secondary ui-table-action" type="button"
      data-ui-modal-open="details-modal" aria-label="Visualizar Área do cliente">
      <i data-lucide="eye" aria-hidden="true"></i> Visualizar
    </button>
  </div>
</td>

O exemplo de botão exige um dialog com id details-modal e o contrato de modal do catálogo. Links navegam; botões executam operações. Ajuste destino e nome acessível ao registro real. Não aplique o estilo globalmente a links comuns, menus, ordenação ou exportações. As Data Tables atuais não têm coluna de ações: não acrescente colunas sem necessidade; ao adicionar, exclua controles dos dados exportados pela integração.

Copy to Clipboard

Testar os três exemplos. Use um botão type="button" com data-ui-copy-target apontando para um ID único, sem #. O alvo é o input/textarea ou code, nunca a caixa que contém botões e mensagens.

O componente lê o valor atual dos campos ou textContent de código, sem remover espaços e quebras de linha. Cada botão recebe uma região role="status" independente: Copiando…, Copiado! por dois segundos, aviso de vazio ou erro. O foco permanece no botão.

<label class="ui-label" for="copy-note">Anotação</label>
<div class="ui-copy">
  <textarea class="ui-textarea" id="copy-note">Olá, equipe!</textarea>
  <button class="ui-icon-button ui-copy-button" type="button"
    data-ui-copy-target="copy-note" aria-label="Copiar anotação">
    <i data-lucide="copy" aria-hidden="true"></i>
  </button>
</div>

<div class="ui-copy is-code" data-ui-copy-box>
  <pre><code id="copy-command">python3 -m http.server 4173</code></pre>
  <button class="ui-icon-button ui-copy-button" type="button"
    data-ui-copy-target="copy-command" aria-label="Copiar comando">
    <i data-lucide="copy" aria-hidden="true"></i>
  </button>
</div>

Inclua os assets centrais do tema. Use uma ação por .ui-copy. data-ui-copy-box habilita cópia ao clicar na caixa; não aplique em campos editáveis. Arraste, seleção ativa e controles internos não disparam a cópia da caixa. O botão continua acessível por Tab, Enter e Espaço.

Para documentação, data-ui-copy-docs no contêiner transforma automaticamente todos os pre em caixas copiáveis na inicialização. Não misture essa transformação com caixas manuais no mesmo contêiner. IDs de código existentes são preservados; novos IDs são gerados sem colisão.

A Clipboard API precisa de contexto seguro (HTTPS ou localhost) e permissão do navegador. Em HTTP não seguro, file:// ou permissão negada, a disponibilidade varia: o componente informa o erro e orienta a cópia manual, sem fallback obsoleto. Não lê o clipboard nem registra, transmite ou persiste o conteúdo. Sem JavaScript, o texto continua disponível para seleção manual. Não adicione cópia a senhas ou segredos por padrão.

Contrato de nomes

.ui-* identifica componentes, .is-* representa estados e data-ui-* conecta comportamentos. Não use texto visível como seletor JavaScript.

.ui-button.is-danger        /* componente + estado */
[data-ui-menu]              /* comportamento */
[data-ui-reveal]            /* entrada progressiva */
[data-ui-loading-trigger]   /* loading demonstrativo */
[data-ui-data-table]        /* tabela funcional */
[data-ui-table-sort]        /* coluna ordenável */
[data-ui-table-export]      /* pdf | excel | csv | json | print */
[data-ui-notification-center] /* histórico e leitura */
[data-ui-footer]            /* versão e autoria */
